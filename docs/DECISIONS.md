## 指南主题逐项核对

| 准备主题 | 在本项目中怎样回答 | 实现/限制 |
|---|---|---|
| 不用大模型的原流程 | 表单→查订单→匹配规则→确认建单 | 页面结构化路径可直接演示 |
| Agent必要性 | 非完整表达的工具选择；安全流程固定 | 没有同数据工作流对照优势结论 |
| RAG与状态/记忆边界 | 政策是证据，SQLite是权威状态，会话仅绑定订单 | 无长期Memory |
| 模型/代码责任 | 模型选查询动作，代码管身份、资格、确认与写入 | 模型没有confirm工具 |
| 写操作治理 | 摘要确认、过期、版本重验、幂等、结果查询 | 本地工单，不是退款接口 |
| 调用预算 | 4模型/6唯一工具/单轮2工具、20秒调度预算 | 未做按价格计费硬上限 |
| 指标和基线 | 同语料同排序器的范围过滤消融 | synthetic、family holdout，非独立盲测 |
| 失败复现 | 错范围政策、虚假上传承诺、丢响应 | 原始记录和故障注入均保留 |
| 防止回归 | 57项测试，CI执行旧服务和新工作台 | 模型真实测试不放入无密钥CI |
| 扩容判断 | 关注模型配额、单写锁、进程内限流 | 未跑生产规模压测 |
| 标识关联 | 请求、会话、运行、工具调用和动作各自独立 | HTTP header、runs/events/actions表 |
| 人工确认恢复 | 暂停草稿持久化；恢复重验再写入 | 不依赖LangGraph内存checkpoint |
| 不可信输入 | 用户/模型输出不改变owner；内部资料不进公共检索 | 非完整Prompt Injection防御证明 |
| 框架与自研边界 | LangGraph执行图，Pydantic验形状；业务约束另写 | OpenAI兼容调用不是自研模型 |
| 证据等级 | 合成离线实验、真实模型API、HTTP/浏览器、本地故障注入 | 没有生产事故或商业收益数据 |

## 两项主要ADR

### ADR-01：用确定性Workflow包围局部Agent

约束：可变自然语言入口，但错误写入有成本。候选：纯RAG、纯表单、完全自主Agent。选择：保留表单，Agent只能调用读工具和准备草稿；用户确认独立于模型。代价：更多代码与状态，无法一句话全自动完成。验证：未确认无工单、越权拒绝、过期/状态变化拒绝、模型错误执行承诺被拦截。如果真实业务证明路径固定且表单更好，保留纯Workflow即可。

### ADR-02：先解决适用性，再研究语义重排

约束：政策在不同渠道和购买时期冲突。候选：扩大Top-K、改提示、全量Reranker、范围预过滤。选择：由订单事实确定范围后BM25排序。代价：口语召回依旧薄弱，缺订单时需追问；Top-3可混入同范围其他主题。验证：范围错误清零但仍有9条未命中，说明优化没有掩盖所有问题。后续在冻结集添加向量/混合/Reranker对照，而不是宣称本次已实现。
