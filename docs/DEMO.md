# 工作台使用示例

按 [运行手册](USAGE.md) 启动后打开 http://127.0.0.1:8001 ，输入自己的 API_TOKEN。

## 订单申请

1. 连接服务，选择 A001，查询订单并检查资格。
2. 查看全库与范围过滤两组政策，核对商品、渠道和有效日期。
3. 生成草稿，检查 Action ID、参数摘要和状态。此时尚无工单。
4. 点击确认，记录返回工单号；再次确认应返回同一工单。
5. 刷新页面或重启服务后查询原 Action ID，结果仍存在于 SQLite。

## 边界行为

| 输入 | 预期 |
|---|---|
| A002 | 超出政策时限，不能建立可提交的申请 |
| A003 | 运输破损需人工核验照片；当前页面没有照片上传功能 |
| B001 | 非本人订单，拒绝读取 |
| 过期或版本发生变化的草稿 | 拒绝直接确认，重新核验后起草 |
| 同一动作重复确认 | 返回原工单号 |

## 自动复现异常

`python -m unittest discover -s tests -p 'test_lab*.py' -v` 覆盖并发确认、提交后丢失响应、取消、重启恢复和版本变化。响应丢失通过测试注入，页面不提供故障开关。对照结果见 `../evals/lab_regression.txt` 与 `../evals/lab_http_smoke.json`。

自然语言功能需要有效模型配置；结构化流程无需模型密钥。401 先核对令牌，409 核对订单归属与动作状态；改数据库结构前先停服务并备份数据。
