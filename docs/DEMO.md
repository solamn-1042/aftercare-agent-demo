# 三分钟演示与核验脚本

先按README启动8001端口。用合成数据演示，访问令牌不贴进聊天或截图明文。

## 面向HR：三分钟

1. 输入自己的API_TOKEN，点击“开始演示”。说明本机演示，订单和规则都是虚构的。
2. A001选择质量故障，核对资格：在演示日期下签收4天，可以准备申请。
3. 点击检索对照。指出基线Top-3包含不同渠道，而过滤组限定直营、V2；也指出过滤组仍可能有不相关主题，不能叫全部答案正确。
4. 生成草稿，强调还没提交。点击确认，展开“业务结果”显示工单号。
5. 点击重复确认，工单号不变。解释重复点击或客户端重试不能产生重复业务动作。
6. 切换B001，核对订单显示ORDER_NOT_FOUND_OR_FORBIDDEN；切换A002显示超时限。
7. 展示底部评测，说明30%→90%的统计范围。不要对HR逐个背库名。

## 技术面：可追加六分钟

- 准备一份新草稿，保存Action ID，刷新或重启服务后输入ID恢复；令牌重新输入，不持久化在浏览器。
- 用户取消草稿，再次确认应拒绝。订单或策略改变的恢复测试由自动测试演示，不在公开API暴露修改订单/注入故障的入口。
- 配置模型后输入“A001耳机坏了，请查政策并准备检修草稿”；展开模型记录，说明工具由模型选择，但confirm不在工具列表。
- 查看baseline/lab_agent.json的photo首轮回复与当前回复：模型曾虚构照片上传能力；现由业务状态明确人工处理。
- 运行单项故障测试，讲“数据库已提交、响应丢失”的测试边界和同一Action ID恢复：

```sh
python -m unittest discover -s tests -p test_lab.py -v
```

## 可复现的交付检查

```sh
python -m lab.evaluate
python -m unittest discover -s tests -p 'test_lab*.py' -v
python -m lab.http_smoke --url http://127.0.0.1:8001 --token YOUR_DEMO_TOKEN
```

http_smoke会创建一张虚构演示工单，验证重复确认返回同一号。全部旧版回归需安装requirements.txt后运行`python -m unittest discover -s tests -v`。

## 已实际操作的浏览器验收

Windows Edge：连接、资格、双路检索、草稿、确认、重复确认、跨用户拒绝均已操作；真实截图位于images/workbench.png。未在手机浏览器或真实公网部署中做兼容性认证。页面favicon缺失的404不影响业务；跨用户409是预期拒绝。

## 面试前故障排查

| 现象 | 检查 |
|---|---|
| 401 | 页面令牌是否等于服务API_TOKEN |
| 503 | 服务API_TOKEN是否至少24字符 |
| model_not_configured | .env是否加载；无模型时可使用结构化路径 |
| provider_error | 模型名、账号权限、API可达性；不要循环重试写接口 |
| EXPIRED / STALE | 查询原动作，重新生成草稿并核对，不篡改摘要 |
| SQLite写锁或挂载权限 | 单worker、可写数据目录；容器卷UID与路径 |
| A001重复申请返回旧单 | Demo对同用户、订单、问题类型仅保留一个工单，这是公开的业务唯一约束 |
