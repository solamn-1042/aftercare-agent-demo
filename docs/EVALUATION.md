# 评测口径与失败分析

本目录记录真实执行的固定用例，订单与商店规则为自建合成数据，不能作为任何真实商家的服务政策。

## 三层指标

1. 工程测试：使用脚本化模型响应检查工具白名单、Schema、订单 owner、循环预算、引用、鉴权、并发和审计故障；这是代码回归，不是模型效果。
2. 检索：使用真实 BGE 模型和 Chroma 索引，在 40 条政策题上统计包含 Gold 正文片段的 Hit@3。库中仅 14 个片段，三种检索全部命中，不具备证明普适性能优势的难度。
3. 模型：60 条问题实际调用 DeepSeek，记录模型选择工具、工具是否执行、最终状态、回答和耗时。50/50 预期工具出现仅表示路由符合预期，不代表全部答案正确，也不评价商业价值。

所有计时来自 `perf_counter`，模型评测并发为 2，不含模型首次加载。检索记录显式保存 warmup 时间。用例文件 SHA256 和知识库指纹用于复现；测试集公开，无训练/线上流量参与。它是回归集，不是独立盲测集。

## 首轮发现和修复

| 例子 | 现象 | 处理 |
|---|---|---|
| P05、P28 | 模型生成 `[订单: 待提供订单号]`，旧正则未捕获这种格式 | 改为捕获所有订单引用，逐个核对已授权工具结果；增加回归 |
| P02、P39 | 回复暗示可以查询签收日期、审核结果 | 系统提示明确工具仅返回商品和状态，禁止承诺额外字段 |
| P35 | 说“直接将你转接人工”，但没有执行工具 | 明确只能建议联系人工；不宣称转接成功 |
| P38 | 首轮无可验证引用被拒答 | 第二轮模型调用政策工具并返回有来源答案；不将单次变化归因为稳定提升 |

## 第二轮仍需关注

对保存的 60 条回答进行了 AI 辅助逐条证据审阅，尚非独立人工评分。P07 将“30日内质量问题运费由商家承担”扩展为“30日内可申请退换货”；P18 把30日范围扩展到提交材料要求；O10 将“1工作日内发起退款”压缩为“1工作日内原路退回”。P13 的追问也可能让读者误解为工具能确认具体到账时间。这些属于引用合法但语义不够严格的 Badcase，应保留而不是以检索全命中掩盖。

N09 虽返回 `answered`，正文明确无法确定具体到账时刻，没有编造时间；因此本报告不以 `status == refused` 直接计算“安全正确率”。其他拒答状态也不自动证明模型全部安全。

下一步应增加独立人工标注、未见改写、多文档冲突、政策版本、生效时间和严格事实蕴含测试；若用于真实业务，需结构化抽取已证实字段，并把资格判定交给确定性业务规则。当前 README 与简历只采用可复算的工程和检索指标。
